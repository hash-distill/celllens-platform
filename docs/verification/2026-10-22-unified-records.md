# 结果解读入口与统一实验记录

## 本次调整

- 主导航为研究分析、结果解读、实验记录、数据与方法、使用说明，继续紧凑左对齐。
- `/records` 合并实测与预测记录，默认全部类别，支持类别、状态、关键词和统一分页；不再使用实测/预测两个历史页签。
- `/records?view=results` 复用同一记录组件，仅显示已完成结果，不复制数据；实测与预测详情及比较页归入结果解读栏目。
- 记录操作统一为“结果解读”；进行中、失败、取消及中断记录不提供可用解读按钮，实验名称仍可打开状态详情。
- 实测详情隐藏新建组合表单，保留新建分析入口和现有结果组件。比较入口保留在结果栏目，加入比较仍在预测详情中操作。
- 旧 `/records?view=measured` 链接兼容为实测类别筛选，工作台、首页、使用说明与比较页同步调整。

## 数据与性能边界

沿用现有两个后端列表 API，并行读取两类记录、每类按 100 条逐页读取完整后再全局排序、筛选和分页；不把两个接口的第一页拼接后冒充完整记录。重复 ID、总数变化或提前返回空页会提示刷新，不展示半份历史为完整结果。筛选与分页使用当前加载快照，不重复请求；刷新按钮重新读取，离开页面终止请求。

排序统一按数据库 UTC 时间处理：实测 `measured_store.create` 使用 `datetime.now(UTC)` 写入，但序列化可能无时区；预测接口显式附加 UTC。仅排序归一化，显示仍保留原始时间标注。两类 ID 使用带类别的键，合成数据保持独立标签，开发模拟模式不混入真实实测记录。

当前验证数据量小（11 条）；全量前端合并不是面向海量历史的分页架构。大量记录场景应增加后端统一索引/分页接口。本次未改数据库或 API，也无需重启后台。
