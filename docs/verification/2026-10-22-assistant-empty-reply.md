# AI 解读空正文排查

截图中的旧错误仅在服务 HTTP 200、JSON 响应可解析、`message.content` 为 null 或空白时触发。它不能说明没有任何响应，也不能区分输出上限、仅返回思考、拒绝或其他空正文。

截图输入估算 4,770、输出预算 2,048、上下文 32,768，不触发平台的上下文预算拦截。DeepSeek 官方文档将 `reasoning_content` 与正式 `content` 分开，并说明思考模式及输出长度选项。较小输出预算在思考阶段耗尽是合理候选原因，但旧响应没有保存，因此此次请求的具体结束原因未得到确认。不能将模拟响应的复现当成用户请求的原始记录。

修复：后端按返回的结束原因区分输出预算耗尽、仅思考、拒绝、工具调用和普通空正文；只返回正式正文，不用思考过程替代科研结论。前端兼容旧后台的空正文错误，以“可能”解释思考预算原因，并提供调整设置入口；DeepSeek 较小预算显示提前提示，设置页补充关闭思考/调整输出长度说明。

本轮未读取或修改用户 API Key，未发送真实模型请求，未自动调高预算或自动重试。用户可先在设置中选择“关闭思考（须模型支持）”并保存；需要思考时可尝试输出长度 8,192，再重新预览和发送。增加上下文窗口不能代替增加输出长度。

验证：104 项相关后端测试、13 项相关前端测试通过；Ruff、BasedPyright、前端类型检查及生产构建成功。新增用例先复现 7 项失败，修复后通过；覆盖空正文结束原因、正文与思考分离、错误信息不泄露思考/密钥、旧后台兼容及不自动重试。浏览器确认模型设置入口可用。真实提供商生成效果尚未复测。

前端生产构建已更新，刷新生效。当前后台不是自动重载模式，本次未停止或重启后台；后端新诊断需正常重启服务后生效。已有实测/预测结果不受 AI 解读失败影响。
