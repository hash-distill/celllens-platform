# 两名代码成员的实施分工

## 成员 A：后端与模型（当前主线）

负责资产注册、STATE 真实推理、AnnData 契约、scCellFie、证据指标、任务队列、API、报告与 A6000 部署。接口输出以 OpenAPI 和 `summary.json` 为准。

阶段验收：

1. G0：注册表审计和一个 STATE smoke test；
2. G1：一个请求生成 `predicted.h5ad` 与可查询运行状态；
3. G2：共同基因、覆盖表、任务分数和匹配留出指标；
4. G3：不可变结果、缓存、预计算演示和证据报告；
5. G4：固定硬件上的耗时/显存实测与错误恢复。

## 成员 B：前端与可视化

负责 Vue 工作台、API 客户端、任务状态、四个科学视图、证据侧栏、候选比较和报告入口。只消费公开接口，不解析模型目录或自行重算指标。

阶段验收：

1. G0：用冻结 TypeScript 类型和静态 fixture 搭建页面；
2. G1：联通 catalog、create run、poll status 和 summary；
3. G2：完成 2D 细胞状态、基因响应、代谢任务、验证四个标签页；
4. G3：完成基因—反应—任务联动、候选托盘和全局证据栏；
5. G4：Chrome/Edge 演示、错误态、无 GPU 预计算模式和录屏。

## 冻结接口

- 状态枚举和请求字段以 `backend/app/schemas.py` 为源；`frontend/src/types/run.ts` 镜像它。
- 前端只轮询后端真实阶段，不用计时器伪造百分比。
- 大矩阵留在 H5AD/Parquet，主页面只接收抽样投影和汇总 JSON。
- 后端字段变更必须先改 schema、测试和 OpenAPI，再通知前端。
- 前端需求若需要新数据，先写期望 JSON 示例，由双方确认后再实现。

第三位队员继续负责生物学任务集合确认、失败案例审核、教师测试记录、作品材料和答辩证据整理，不承担两条代码主线的日常冲突合并。
